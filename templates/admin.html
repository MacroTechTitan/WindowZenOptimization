🔄 How to Release an Update

Follow these steps each time you push a new version to users.

🛈 The installed Windows app checks windowzen.macrotechtitan.com/updates/version.json when users click "Check for Updates". Uploading two files to that server is all it takes to push an update — no installer rebuild needed.
🔧 Step-by-Step Release Process
  1. Make your code changes in Replit
    Edit app.py, templates/, or static/ as needed. Test everything using the preview pane before releasing.
  2. Bump the version in Version Manager This page
    Go to Version Manager in the left sidebar. Increment the build number (e.g. 100 → 101) and add changelog entries describing the changes. Click Save & Publish.
  3. Download the project from Replit
    Click the ⋯ menu in the Replit file tree → Download as .zip. Save it to your PC.
  4. Create the update package (latest.zip)
    From the downloaded project, create a new zip containing only these items — this is what users download (not the full installer):
    latest.zip contents: ├── app.py ├── version.json ├── templates/ │ ├── dashboard.html │ ├── landing.html │ └── eula.html └── static/ ├── css/style.css ├── js/app.js └── images/
    On Windows, select those files/folders → right-click → Send to → Compressed (zipped) folder. Name it latest.zip.
  5. Upload to windowzen.macrotechtitan.com/updates/
    Upload exactly these two files to your update server at the path /updates/:
    windowzen.macrotechtitan.com/updates/ ├── version.json ← updated version manifest └── latest.zip ← the update package
    If using cPanel/FTP: upload to the public_html/updates/ folder. If using Cloudflare Pages or similar: add to the repo and push.
  6. Verify the update server Test
    Open a browser and check these URLs return valid responses:
    https://windowzen.macrotechtitan.com/updates/version.json https://windowzen.macrotechtitan.com/updates/latest.zip
    The version.json should return JSON with the new build number. The latest.zip should download.
  7. Users receive the update automatically Done
    When users click Settings → Check for Updates in the installed app, it will detect the higher build number, show the changelog, and offer the Download & Install button. The app downloads latest.zip, replaces the files, and restarts — all without them needing to run the installer again.
⚠ Important Notes
• Always increment the build number in version.json — the app compares build numbers, not version strings
• The latest.zip should not include settings.json or WindowsInstaller/ — preserve user settings
• If you add new Python packages, users will need to reinstall via the full installer — pip packages are bundled by PyInstaller at build time
• Breaking changes to app.py (new routes, new imports) work fine — only new pip packages require a full installer rebuild
• The update script runs as the current user — no admin elevation is needed for app file replacement
• Test updates on a clean install before publishing widely
